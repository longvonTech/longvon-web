# GEO-43-002 conversion measurement

Goal: qualified, real OEM/ODM opportunities and accepted commercial orders, not traffic or model mentions.

## Implemented browser signals

`longvon:oem-conversion` is a local DOM event with only `{name, locale, interest, is_test}`. The optional existing Baidu queue receives `_trackEvent / oem_conversion / name / locale:interest` only for non-test events. No new analytics service, endpoint, cookie, tracking identifier or personal data field is added. If analytics is absent or throws, the inquiry path continues.

- `oem_cta_click`: actual click on a journey stage/primary CTA, not SSR, prefetch or page view.
- `rfq_start`: first focus within that mounted form, once per mount. It is an interaction, not a lead, quote or order.
- `rfq_submit_success`: only after the existing submission promise succeeds. No success event on client validation failure, API error or a populated honeypot. It is a submitted inquiry, not a qualified lead or paid order.

Click coverage is the new journey stage/primary CTAs, not every legacy site link. Form signals also cover existing RFQ entries. Keep interest cohorts separate: do not divide all site form starts by this subset of CTA clicks.

Interest values are allowlisted: sample evaluation, pilot evaluation, production feasibility, raw PPG, or other. No contact name/email/phone, free-text brief, full URL or raw query is emitted. Backend first/latest attribution capture remains unchanged; event interest does not manufacture a campaign or AI recommendation.

## Synthetic/test handling

Localhost/127.0.0.1, explicit `test_run` query presence, `[TEST`/SYNTHETIC name markers or reserved example/test email domains produce `is_test:true`. A boolean-only tab-session flag retains a TEST classification across internal navigation; it is not a visitor identifier. These events remain visible in the local QA DOM stream but are never pushed to the commercial Baidu queue. Use `test_run` before the first interaction when testing a real domain; otherwise a start before a later TEST name is entered cannot retrospectively know that it was a test. A start is never counted as a commercial lead.

Browser signals are diagnostic only. Final commercial reporting must also exclude soft-deleted/test CRM records, synthetic/test names and reserved test email domains. Do not rely solely on a client flag or HTTP201. Existing P0 TEST rows remain excluded; this issue does not alter or submit production data.

## Sales-verified conversion stages (not generated by the browser)

- Qualified lead: a human has verified a genuine organization/contact, relevant use case/market, technical fit to investigate and plausible procurement intent. Link to a real inquiry record; do not infer qualification from page visits, a filled form or a large forecast.
- Sample order: an identifiable sample order has been accepted with agreed scope/terms. Record the order reference and payment status separately; a sample request is not proof of an order or payment.
- Pilot order: an accepted pilot order/reference and agreed model/configuration/quantity. Pilot interest or an estimate is not a production commitment.
- Mass-production order: a real accepted order/reference for production. Annual forecast, quotation, samples or a pilot do not establish this stage or reserve capacity.

These are reporting criteria, not new backend states or automatic CRM transitions. Existing commercial fields/order evidence need a separate owner-confirmed mapping; no schema, query behavior or approval flow is modified here.

## Simple weekly reporting recommendation

Report distinct real qualified OEM/ODM leads, sample orders, pilot orders and production orders by cohort, with denominators and missing-evidence counts. Use deduplicated inquiry/customer/order references in existing approved reporting, not raw event counts. Show page CTA→form start→inquiry as upper-funnel diagnostics, then inquiry→qualified→accepted order as the business funnel. Report sample/pilot/production order count and verified value separately; unknown values stay UNKNOWN. Do not sum repeat events, forecasts or multiple contacts from the same opportunity as new orders.

Segment by locale, first-touch campaign/channel and latest-touch campaign using existing stored UTM/AI/referrer fields. An AI-source label is attribution evidence, not proof of an AI recommendation, a qualified customer or a sale. Track lead qualification and accepted-order conversion alongside traffic. This issue supplies the definitions and frontend signals, not a deployed dashboard or a fabricated performance uplift.
