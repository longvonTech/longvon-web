What 100Hz means — and what to evaluate

100Hz describes a sampling frequency of 100 samples per second. It does not by itself specify continuous recording, wireless streaming latency, buffering duration or cloud API update frequency. Start with the signal and integration requirements your R&D team needs to evaluate; confirm the actual sampling and delivery configuration in the technical SOW.

Device data and cloud algorithms are different scopes

Partner SDK / customer-owned App
The SDK provides agreed device-connectivity and data pathways. Customer-owned App integration is supported subject to project evaluation; confirm the supported ring model, SDK platforms and available data before planning implementation.
Cloud algorithms / Cloud API
Many health metrics use LONGVON cloud algorithm services. Raw-data access does not mean that all algorithms run offline, that every metric is available through an API, or that unrestricted BLE protocol access is included. Define the device, App and cloud responsibilities separately.

Agree the technical scope before implementation

Use discovery, NDA and the technical statement of work to confirm the following. These are evaluation questions, not published specifications or default entitlements.

  • Hardware and sampling: Supported ring model and hardware revision; required signals; sampling configuration and any operating constraints.
  • Data delivery: Raw-data format, units, timing information, transfer method and buffering behavior. No packet format, retention period or latency is specified here.
  • App and SDK integration: Customer App ownership, target platforms, SDK availability, documentation and the agreed integration/support scope.
  • Permissions and cloud scope: Who may access/use the data; handling requirements; authorized algorithm outputs; any cloud/API dependencies and environments.

Frequently Asked Questions

Does LONGVON provide a public self-serve SDK download?

No. SDK and cloud API access are enabled under OEM/ODM or technology partnerships. Scope is defined per project.

Can partners access 100Hz PPG raw data?

Yes, 100Hz PPG raw data access can be discussed for qualified OEM/ODM partners as part of the technical scope.

Do all health algorithms run fully offline on customer hardware?

No. LONGVON does not claim that all algorithms run independently on customer devices. Many health metrics are delivered through LONGVON cloud algorithm services; the on-device vs cloud split is defined per project.

Is an unrestricted Bluetooth protocol provided to every customer?

No. Interfaces are provided as documented for the agreed project. Unrestricted Bluetooth protocol access is not a default public offer.

Can we use our own App?

Yes. Customer-owned App integration via SDK/API is a supported model and is evaluated during technical consultation.

How are SDK, algorithm licensing, technical support, and cloud services separated?

SDK covers device connectivity and data pathways; algorithm licensing defines which metrics/models are authorized; technical support is provided in agreed windows; cloud services host cloud algorithms and data APIs and are scoped/priced separately under the cooperation model.

Does 100Hz raw PPG mean continuous real-time BLE streaming?

No continuous-streaming or latency guarantee is made here. 100Hz describes sampling frequency. Qualified partners discuss the agreed SDK pathway; sampling configuration, transfer and buffering behavior must be confirmed in the technical SOW. Unrestricted BLE access is not a default offer.

Which ring model, raw-data format and SDK platform should we use?

Confirm the supported ring model, hardware revision, SDK platforms, raw-data format and delivery scope during technical consultation. This page does not publish a universal model/platform compatibility list or packet specification.

Can raw PPG replace LONGVON cloud algorithms or establish a diagnosis?

No such claim is made. Many health metrics depend on LONGVON cloud services; raw-data access and algorithm authorization are separate scopes. Ring1C is not a medical device, and raw-signal access is not evidence of diagnostic capability or clinical validation.

What should we provide for a raw PPG technical consultation?

Share your intended use, target App platforms, raw-signal requirements and data-handling needs. Discovery/NDA and a technical SOW establish the supported hardware, SDK/data pathway, permissions and cloud responsibilities. SDK access is project-scoped, not a public self-serve download.
